# 管理后台 API 当前状态

更新日期：2026-09-29

本文记录 `fishing-notes-admin-api` 当前已实现的管理接口和后续建设方向。接口路径、请求参数和响应字段以实际 handler、Swagger 和权限目录为准。

## 已完成接口

| 模块 | 当前能力 |
| --- | --- |
| 认证 | 管理员登录、当前用户、当前权限和菜单查询 |
| RBAC | 角色列表、新增、编辑、删除、权限定义、用户角色查询、用户角色绑定、角色权限绑定 |
| 管理员 | 后台用户分页查询、用户详情、新增、编辑、启用/停用和密码重置 |
| 钓点评审 | 钓点评审列表、详情、发布和下线 |
| 钓点纠错 | 纠错列表、采纳和驳回，空结果返回空列表 |
| 公共钓点申请 | 分页/关键词/状态查询、详情、审核通过新建或合并钓点、驳回及操作审计 |
| 发现页横幅 | 分页/关键词/发布状态查询、详情、创建、编辑、发布/隐藏及操作审计 |
| 发现内容 | 内容列表、详情、新建、编辑、发布和下线 |
| 鱼种图鉴 | 鱼种列表、详情、新建、编辑和展示/隐藏 |
| 工程基础 | go-zero 服务、配置示例、权限中间件、Swagger 路由和初始化脚本；生产仓储统一使用 GORM |

## 当前边界

- 管理后台已经可以支撑基础登录、钓点评审、纠错处理、内容维护、鱼种维护和用户状态管理。
- 角色权限和用户角色关系已经提供替换写入接口，管理员账号也支持新增、编辑和密码重置。
- 统一审核任务已经覆盖钓点评审、用户提交钓点和钓点纠错；审核历史 API 与工作台时间线已完成，结构化纠错字段差异和局部采纳已接入。
- 公开渔获图片可在独立审核队列中预览、通过或驳回；依赖小程序 API migration `000049`，私密记录图片不会进入审核队列。
- 已接入公开鱼情审核任务与通过/驳回操作；部署前必须先执行小程序 API migration `000043`。媒体审核、评论审核和举报处理仍未覆盖。
- 公共钓点申请审核已接入：审核详情包含申请图片、坐标、鱼种和描述；审核通过可创建公共钓点或并入已有钓点，驳回要求填写用户可见说明，操作写入审计日志。依赖 API migration `000050` 与新增权限同步脚本。
- 管理后台 API 与小程序 API 共用业务数据库时，需要继续明确迁移顺序和状态字段边界。

## 维护规则

1. 新增后台能力必须同步权限目录、路由、handler、Swagger 和管理端 API 调用。
2. 所有审核、删除、封禁和批量操作必须记录操作者和业务对象。
3. 空列表返回成功响应和空数组，基础设施错误必须保留原始错误语义。
4. 管理后台只负责运营和审核，不在后台 API 中复制小程序页面逻辑。

## 审计留痕

- 表：`admin_audit_logs`，由 `scripts/bootstrap_admin.sql` 显式初始化。
- 新增审核历史接口使用 GORM 查询和写入，复用 go-zero 管理的数据库连接池，不额外创建连接池。
- 字段：操作者 `actor_user_id`、动作 `action`、资源类型 `resource_type`、资源 ID `resource_id`、结构化详情 `detail_json` 和创建时间。
- 当前已记录：管理员账号、管理员角色绑定、角色维护、角色权限、钓点审核、钓点纠错、文章、鱼种和业务用户状态变更。
- 审计写入失败会记录服务端告警，但不会把已成功完成的业务写操作返回为失败，避免客户端重复提交。
- 服务启动不会创建表或同步权限；部署前需单独执行初始化脚本，并将脚本执行结果纳入发布检查。
- 既有环境需执行 `scripts/sync_permissions.sql` 并在角色页面授权；新环境的 `bootstrap_admin.sql` 已包含超级管理员权限。执行前需按发布流程确认数据库目标和备份。
- Banner 使用 API 已有 `discover_event_banners` 表；测试/预发仍需确认表结构、权限增量脚本和真实读写链路已执行。
